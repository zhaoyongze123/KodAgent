# 规划院 OA 三套目标环境配置

三套目标环境各自维护一份非机密 profile 和一份服务器侧机密 overlay：

```text
script/docker/env/targets/
├── local.env                    # 本地 Docker Compose
├── local.frontend.env
├── local.secrets.env.example
├── 103.env                      # 103 验证服务器，宿主机 JAR + 既有 Nginx
├── 103.frontend.env
├── 103.secrets.env.example
├── production.env               # 正式内网，宿主机 JAR + 既有 Nginx
├── production.frontend.env
└── production.secrets.env.example
```

真实密码不写入仓库。首次使用某个环境时，在服务器或部署机上复制对应模板：

```bash
cd /Users/mac/项目/若伊部署
cp script/docker/env/targets/local.secrets.env.example \
   script/docker/env/targets/local.secrets.env
cp script/docker/env/targets/103.secrets.env.example \
   script/docker/env/targets/103.secrets.env
cp script/docker/env/targets/production.secrets.env.example \
   script/docker/env/targets/production.secrets.env
chmod 600 script/docker/env/targets/*.secrets.env
```

分别填写 `MYSQL_ROOT_PASSWORD`、`MASTER_DATASOURCE_PASSWORD`、`SLAVE_DATASOURCE_PASSWORD` 和 `REDIS_PASSWORD`。三个文件不要使用同一个环境的临时密码，也不要提交 Git。

## 加载和校验

在当前终端加载目标 profile：

```bash
source script/docker/env/load-target-env.sh 103
```

只显示非机密配置并校验结构：

```bash
bash script/docker/env/validate-target-env.sh local
bash script/docker/env/validate-target-env.sh 103
bash script/docker/env/validate-target-env.sh production
```

校验器不会输出密码；如果尚未创建 secrets 文件，会明确提示，不能据此直接部署。

## 本地环境

本地环境使用独立端口和 Compose 数据卷。填写 `local.secrets.env` 后执行：

```bash
TARGET_ENV=local bash script/docker/deploy.sh
```

本地 profile 的默认端口是前端 `18080`、后端 `48080`、MySQL `13306`、Redis `16379`。离线预览服务单独执行：

```bash
bash script/docker/intranet/apply-preview-target.sh local
```

## 103 和正式内网

`103` 与 `production` 的 `DEPLOY_MODE=manual`，实际运行形态是宿主机 JAR 加现有 Nginx。`deploy.sh` 会识别这两个 profile 并停止，不会把现有内网服务误重建成 Docker Compose。代码更新脚本在目标服务器上按现有手工更新目录执行：

```bash
sudo bash /data/oa-manual/update/update-oa-on-target.sh \
  check /data/oa-manual/update/incoming/<发布目录>
sudo bash /data/oa-manual/update/update-oa-on-target.sh \
  apply /data/oa-manual/update/incoming/<发布目录>
```

`update-oa-on-target.sh` 的默认值就是当前 `/data/oa-manual` 手工部署目录；如果需要在仓库中预演不同目标，可在拥有完整仓库相对路径的环境中设置 `TARGET_ENV=103` 或 `TARGET_ENV=production`，脚本会从 profile 读取 JAR 目录、数据库容器、Nginx 容器、前端目录和健康检查地址。数据库、Redis、KodBox 不会被普通代码更新停止或覆盖。

离线预览服务按对应 profile 单独启动，容器内部端口固定为 `8012`，宿主机只绑定 `127.0.0.1:18012`，对外地址由现有 Nginx 暴露为 `18112`：

```bash
bash script/docker/intranet/apply-preview-target.sh 103
bash script/docker/intranet/apply-preview-target.sh production
```

预览脚本需要和 `script/docker/env/targets/` 一起保留，建议从仓库目录执行；若要在服务器直接执行，需按仓库相对目录同时上传 `script/docker/env/`、`script/docker/intranet/` 两个目录，不能只上传单个脚本。

如果脚本位于仓库目录，则使用仓库中的同名脚本。正式 profile 会强制设置：

```text
KK_BASE_URL=http://192.168.2.10:18112
前端预览地址=http://192.168.2.10:18112/onlinePreview
```

## 端口和事实源

| 环境 | OA 前端 | OA 后端健康检查 | MySQL 映射 | Redis 映射 | 预览对外地址 |
| --- | ---: | ---: | ---: | ---: | --- |
| local | 18080 | 48080 | 13306 | 16379 | `http://127.0.0.1:18112` |
| 103 | 18080 | 48180 | 33306 | 36379 | `http://192.168.1.103:18112` |
| production | 18080 | 48180 | 33306 | 36379 | `http://192.168.2.10:18112` |

Profile 是环境差异的唯一配置入口；前端构建只读取对应的 `*.frontend.env`，后端/Compose 只读取对应的 profile 加 secrets overlay。不要在镜像、JAR、前端源码或脚本中再写入 103 或正式环境地址。
