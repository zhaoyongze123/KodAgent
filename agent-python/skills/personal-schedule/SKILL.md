# 个人日程 Skill

## 意图边界

- “我的日历”“今天有什么安排”属于查询类动作。
- “提醒我”“安排一个日程”属于创建类动作。
- “把刚才的日程改到明天”属于修改类动作，需要唯一的已有个人日程事实。
- “取消这个日程”属于取消类动作，需要唯一的已有个人日程事实。

具体 action_id 必须从当前 route_conversation 工具 schema 的 enum 选择；本 Skill 不定义动作名称。

## 澄清策略

- 创建日程至少需要标题、开始时间和结束时间。
- 修改或取消不能把会议预约当作个人日程，也不能猜测来源 ID。
- 多条候选记录时先询问用户选择；时间冲突应如实说明。
- 草稿生成、用户确认和最终提交必须分别表达。

字段提取样例：

- “明天上午我有什么安排”应选择查询语义，把相对日期转换成明确日期或完整时间范围。
- “明天 9 点安排一个项目例会到 10 点”应选择创建语义，同时提供 `title`、`start_time` 和 `end_time`。
