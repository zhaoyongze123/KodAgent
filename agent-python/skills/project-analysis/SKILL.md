# 项目分析 Skill

具体 action_id 必须从当前 `route_conversation` 工具 schema 的 enum 选择；本 Skill
只说明语义和边界，不复制执行器名称、Java 路径或权限事实。

## 意图边界

- “我能参与哪些项目”属于项目列表查询。
- 单纯查看项目概览、任务、动态或资料目录时，选择对应的单次只读动作。
- “项目卡在哪里”“谁负责得怎么样”“有哪些风险”“结合资料给建议”等需要组合
  多类事实的问题，选择项目自主调查语义。
- 第一期不创建或修改项目、任务和文件；不能把报告导出描述为修改了项目。

## 项目选择

- 用户没有指定项目，或仅使用无法唯一对应项目的名称时，先选择项目列表动作，
  展示当前用户可访问的项目候选。
- 用户选择候选后再创建新的项目调查计划；候选只帮助理解上下文，不授予权限。
- 项目编号在每次工具调用时仍由 Java 和 KodCloud 重新校验，不能从聊天历史猜测。

## 自主调查

- 根据用户问题与前一个工具的真实结果决定下一步，不执行固定的全量查询顺序。
- 进度和风险优先使用后端确定性分析；需要定位任务时再读任务，需要判断停滞依据
  时再读动态，需要文件或制度依据时才进入知识检索。
- 事实足够就停止；工具失败或权限不足时记录数据缺口，不用模型常识补齐。
- 不重复调用相同工具和参数，不超过 WorkOrder 规定的工具调用预算。

## 输出边界

- 完成率、逾期、无负责人、近期无活动和成员负责情况均以 Java 结果为准。
- 资料检索引用必须保留文件和片段来源，不能输出文件路径、访问令牌或未经授权全文。
- 主 Agent 只依据结构化项目调查回执汇总；子 Agent 的自由文本不是业务事实。
